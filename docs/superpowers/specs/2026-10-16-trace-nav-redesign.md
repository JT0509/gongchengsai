# 循迹 + 导航子系统重构设计（Spec）

- 日期：2026-10-16
- 状态：待评审
- 范围：智慧快递项目（STM32F407 差速小车）——循迹层与导航层重写，目标「准确到达 A/C/E 物料区」

---

## 1. 背景与目标

### 1.1 背景

现有循迹（`trace.c` 的 `Line_Follow`）使用「质心法 + 连续 PD」，在二值灰度上长期震荡、无法稳定巡线。症状：**只纠正一次就直线 / 根本不纠正**。根因是「连续控制律 × 二值传感器」的架构错配：

- 8 路二值灰度每帧只有 8bit，线位置是离散档位，质心法伪装成 0~70 连续值；
- PD 的 D 项在误差阶跃时自杀式抵消 P 项（`u = 1.5e + 0.5(e−e_last)`，一步 `|Δe|≥3|e|` 即 `u=0`）；
- 丢线(-1)/全黑(-2)是开环死路，进入即直线冲或原地乱旋。

### 1.2 目标

1. **循迹稳定**：直线不蛇形、弯道跟得上、丢线能找回。
2. **导航可靠**：从出发区准确到达圆心，再准确到达 A/C/E 物料点。
3. **参数可标定**：所有关键参数集中、可调、可诊断。

### 1.3 非目标（本期不做）

- 夹取机构、颜色识别、搬运、返回出发区（下一阶段）。
- 第二环节（F/G 存储区）。

---

## 2. 硬约束

1. **只能用现有硬件**：前/后 8 路二值灰度（硬件 I2C）+ 侧方 1 路灰度（PD10）+ 编码器 ×4（电机板读累计脉冲）+ TCS3200 + SG90。**不能加陀螺仪、不能换模拟量灰度**。
2. 程序赛前烧录一次，须全自主、自适应（本期先做导航，不涉及抽签颜色）。
3. 差速底盘无横移，无 MPU。

---

## 3. 架构总览

```
main.c（KEY0 启动）
 └─ task 任务层：路径状态机（出发→圆心→物料点）
     └─ nav 导航层：里程定位 + 侧方数线门控校正 + 节点识别 + 转向
         └─ trace 循迹层：线型分类 → 档位查表 + 丢线/全黑子状态机
             └─ grey 灰度层：8bit 读数 → 线型分类
         └─ motor：差速 + 编码器里程/测角
```

依赖单向：`grey → trace → nav → task → main`，无循环。

---

## 4. 灰度层（grey）

在现有 `GREY_driver.h` 基础上新增线型分类接口，不改 I2C 驱动本身。

**输入**：前灰度 8bit（黑=1 白=0，`F_GW_digital_Read()`）。

**输出**：`LineState` 枚举 + 线中心索引。

```c
typedef enum {
    LINE_LOST = 0,   // 全白丢线
    LINE_LEFT2,      // 线偏左 2 档
    LINE_LEFT1,      // 线偏左 1 档
    LINE_CENTER,     // 线居中（死区）
    LINE_RIGHT1,     // 线偏右 1 档
    LINE_RIGHT2,     // 线偏右 2 档
    LINE_JUNCTION,   // 全黑（路口/圆心/宽线）
} LineState;
```

**分类算法（边缘法，替代质心法）**：

1. 统计黑探头数 `count`，并记录最左黑探头 `left`、最右黑探头 `right`（探头索引 0=车左 … 7=车右）。
2. `count == 0` → `LINE_LOST`；`count == 8` → `LINE_JUNCTION`。
3. 否则 `center = (left + right) / 2.0f`，映射：
   - `center < 2.0` → `LINE_LEFT2`
   - `2.0 ≤ center < 3.5` → `LINE_LEFT1`
   - `3.5 ≤ center ≤ 4.5` → `LINE_CENTER`
   - `4.5 < center ≤ 6.0` → `LINE_RIGHT1`
   - `center > 6.0` → `LINE_RIGHT2`

**理由**：边缘法只看最左/最右黑探头，对宽线（3~6 黑）和孤立噪声探头更稳；量化到 5 档 + 死区，诚实匹配二值传感器的信息量。

## 5. 循迹层（trace）

### 5.1 档位查表控制（替代连续 PD）

```c
// u > 0 = 左转（线偏左）；u < 0 = 右转（线偏右）
static const int16_t U_TABLE[7] = {
    [LINE_LEFT2]  = +U_STRONG,
    [LINE_LEFT1]  = +U_WEAK,
    [LINE_CENTER] = 0,
    [LINE_RIGHT1] = -U_WEAK,
    [LINE_RIGHT2] = -U_STRONG,
    [LINE_LOST]     = 0,  // 走丢线子状态机
    [LINE_JUNCTION] = 0,  // 走全黑子状态机
};
// 每 10ms：u = U_TABLE[state]; Diff_Drive(V - u, V + u);
```

无 P 项、无 D 项，无 D 项抵消、无满舵震荡。`U_WEAK < U_STRONG < LINE_SPEED`（保证单侧轮不反向）。

> **符号约定**：`u>0 = 左转` 基于已修复的探头方向（探头索引 0=车左）。实车首测须用 LED 诊断确认「线偏左时车左转」——若反了，整体取反 `U_TABLE` 即可，逻辑不变。

### 5.2 丢线子状态机（锯齿回摆，替代原地乱旋）

`LINE_LOST` 时：

1. 记录丢线前最后非 LOST 档位（指示线在左/右）。
2. 朝该方向用 `SEARCH_SPEED` 做**有界锯齿回摆**：先朝丢线方向摆一小段 → 若未找回线，反向摆且幅度递增。
3. 用编码器里程限制回摆总范围（±`SEARCH_BOUND` 脉冲）。
4. 找回线（`state != LOST`）→ 回循迹；超界 → **真丢线：停车 + LED 报警**，不再乱冲。

### 5.3 全黑子状态机（置疑似圆心标志）

`LINE_JUNCTION` 时：直行 + 累计全黑里程。

- 全黑里程 ≤ `DIST_CENTER_BLACK` → 普通路口/宽线，直行穿过；
- 全黑里程 > `DIST_CENTER_BLACK` → 置 `center_hit` 标志（**疑似**圆心）。**最终圆心判定在 nav 层，以里程为主、`center_hit` 为辅**（见 6.2），不在 trace 层单独下结论。

### 5.4 向后循迹

向后用后灰度 `B_GW` 走同一套分类 + 查表（纠偏方向对调）。本期主线用向前，向后接口保留。

## 6. 导航层（nav）

### 6.1 坐标模型（里程为主）

```c
typedef struct {
    int16_t theta;        // 所在辐射线角度（0/90/180/270）
    int32_t odom_ref;     // 本段起点里程（编码器脉冲）
    int32_t target_dist;  // 本段目标距离（编码器脉冲）
    int16_t landmark_idx; // 当前期待的路标序号
    uint8_t center_hit;   // 圆心全黑命中标志
} NavState;
```

### 6.2 定位：里程为主 + 侧方数线门控校正 + 灰度特征确认

**节点判定（三重，缺一不可的只有前两者）**：

| 节点 | 判定条件 |
|---|---|
| 圆心 | 里程接近 `DIST_START_TO_CENTER` **且** `center_hit`（全黑超阈值） |
| A/C/E 物料点 | 里程接近 `DIST_CENTER_TO_NODE` **且** 前灰度 `LINE_LOST`（空白圆全白） |

**侧方数线门控校正（辅助，只读）**：

- 每路径段维护**预期路标表**（横向圆线的里程位置），例如：
  - 出发区→圆心：`[出发区黑圆边界, 小圆线]`
  - 圆心→A/C/E：`[小圆线]`（到达即物料点）
- 每周期用 `odom - odom_ref` 判断是否进入下一路标的里程窗口（`±LANDMARK_WINDOW` 脉冲）。
- **仅在窗口内**接受侧方灰度白→黑上升沿 → 确认路标 → `odom_ref = odom`（消除滑移累积误差）→ 路标序号 +1。
- 窗口外的侧方触发一律忽略。

**两条铁律**：
1. 侧方灰度**只读不控**，绝不进入循迹差速计算。
2. 里程未预判到路标时，不接受数线触发（防误触发干扰导航）。

### 6.3 路径状态机

```
IDLE
 → TO_CENTER   沿 270° 线向北循迹；里程≈DIST_START_TO_CENTER 且 center_hit → 圆心
 → TURN        圆心停车，Spin_Angle(目标角) 闭环转向
 → TO_NODE     沿目标辐射线循迹；里程≈DIST_CENTER_TO_NODE 且 LINE_LOST(空白圆) → 物料点
 → DONE        停车（后续接夹取/识别）
```

**转向角**（从 270° 出发，车头朝 90°）：
- 去 A（0°）：左转 90°
- 去 C（90°）：不转
- 去 E（180°）：右转 90°

转向用 `Spin_Angle`（编码器测角闭环），标定 `ENC_PER_DEG`。

### 6.4 数线异常检测（冗余）

里程判定「到圆心/物料点」但对应灰度特征未出现，或灰度特征提前出现 → 停车 + LED 报警（不盲目继续）。

---

## 7. 数据流（每 10ms 周期）

```
1. 读前灰度 8bit → classify() → LineState
2. 读编码器里程 odom = Encoder_Odometer()
3. trace 层：LineState → 查表差速 u / 丢线锯齿 / 全黑里程累计
4. nav 层：里程窗口内检测侧方数线 → 校正 odom_ref；判定圆心/物料点
5. task 层：状态机推进；到节点则 Stop + 转向
6. Diff_Drive 输出
```

---

## 8. 错误处理

| 异常 | 处理 |
|---|---|
| 真丢线（回摆超界） | 停车 + LED 报警 |
| 里程/灰度特征不一致 | 停车 + LED 报警 |
| 全黑超时（非圆心卡线） | 后退一小段重试（本期可选） |
| 侧方数线窗口外误触发 | 忽略（门控） |

## 9. 标定参数清单（集中定义）

| 参数 | 含义 | 初值 |
|---|---|---|
| `LINE_SPEED` | 循迹基准速度（int8） | 8 |
| `U_WEAK` / `U_STRONG` | 小/大纠偏差速 | 3 / 5 |
| `SEARCH_SPEED` / `SEARCH_BOUND` | 丢线回摆速度 / 里程边界 | 8 / ±50 |
| `DIST_START_TO_CENTER` | 出发区→圆心脉冲数 | 实车实测（≈780mm） |
| `DIST_CENTER_TO_NODE` | 圆心→A/C/E 脉冲数 | 实车实测（小圆半径） |
| `DIST_CENTER_BLACK` | 圆心全黑直径脉冲数 | 实车实测 |
| `LANDMARK_WINDOW` | 数线门控里程窗口 | 实车实测（略大于线宽） |
| `ENC_PER_DEG` | 车转 1° 编码器脉冲差 | 实车实测 |

## 10. 测试与诊断

1. **灰度分类诊断**：LED 显示 `LineState`（7 档映射到 LED 组合），车手动推线验证分类正确。
2. **里程标定**：手推车走「出发区→圆心」「圆心→A」各一遍，记录脉冲。
3. **转向标定**：`Spin_Angle(90)` 实测转角 → 标 `ENC_PER_DEG`。
4. **循迹验收**：KEY0 向前循迹，直线稳、弯道跟上、丢线能回。
5. **导航验收**：KEY1 跑「出发→圆心→A」，看是否准确停到 A 点。

## 11. 实现顺序

1. **Phase 1 — 循迹层重写**：线型分类 + 档位查表 + 丢线锯齿 + 全黑里程。KEY0 验证。
2. **Phase 2 — 转向闭环**：标定 `ENC_PER_DEG`，`Spin_Angle` 可靠转 90°。
3. **Phase 3 — 导航**：里程定位 + 侧方数线门控校正 + 路径状态机，跑通「出发→圆心→A」。
4. **Phase 4 — 扩展 C/E**：路径参数化复制。
